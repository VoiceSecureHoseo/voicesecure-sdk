## 1. 개요 (Executive Summary)

**VoiceSecure SDK**는 스마트폰·IoT 환경에서 사용자의 음성을 **딥보이스(음성 복제 AI)** 로부터 보호하는 임베디드 SDK다. 사용자가 음성을 발화하면, SDK가 사람 청각으로는 원본과 거의 구별되지 않으면서도 AI 화자 식별·음성 복제 시도는 실패하도록 변형된 음성을 실시간 출력한다.

**핵심 기술**: 강화학습으로 학습된 노이즈 정책 + 심리음향 마스킹 제약 + 다중 평가 모델 기반 reward.

**최종 산출물**: Raspberry Pi에서 동작하는 Phase 1 prototype + Android SDK Phase 2 패키지.

---

## 2. 배경 및 문제 정의

### 2.1 시장 문제

오픈소스 음성 복제 모델(OpenVoice2, XTTS 등)이 짧은 음성 샘플 한 개만 있어도 임의의 텍스트를 그 화자 목소리로 합성할 수 있는 시대가 됐다. 이는 다음 위협을 만든다:

- **금융 사기**: 가족 목소리 복제로 송금 요구
- **신원 도용**: 음성 본인인증 우회
- **정치적 허위정보**: 공인 목소리로 가짜 발언 생성
- **무단 데이터 수집**: 빅테크가 사용자 음성으로 모델 학습

### 2.2 기존 해결책의 한계

| 접근 | 한계 |
|---|---|
| 음성 출력 차단 | 통화·메신저 기능 마비 |
| Pitch shift 등 단순 변조 | 음질 손상 + 강한 모델은 여전히 화자 식별 |
| 서버 기반 익명화 | 프라이버시 도구가 데이터 수집 → 모순 |
| 학술 논문 시스템 | SDK·실시간성·온디바이스 미고려 |

### 2.3 우리의 차별점

- **온디바이스**: 음성이 기기 밖으로 안 나감
- **실시간**: 200ms 이내 latency
- **학습된 정책**: 단순 규칙 기반이 아닌 RL이 발화별로 최적 변형
- **수학적 음질 보장**: Psychoacoustic Masker로 audibility hard-constraint
- **검증 가능**: 다중 화자 인식 모델 + TTS 복제 + ASR로 측정

## 3. 목표 사용자 (Target Users)

### 3.1 1차 사용자 (End Users)

| 페르소나 | 특성 | 핵심 니즈 |
|---|---|---|
| **프라이버시 민감 일반인** | 30-50대, 공인이 아니지만 보이스피싱 우려 | 통화 시 자동 보호, 설정 단순 |
| **공인** | 정치인, 연예인, 인플루언서 | 모든 음성 출력에 보호, 강한 방어 |
| **기업 임원** | 금융·보안 업계 | 회의 녹음·통화 보호, 감사 가능성 |

### 3.2 2차 사용자 (Integrators — SDK를 자사 앱에 탑재할 개발자)

| 페르소나 | 특성 | 핵심 니즈 |
|---|---|---|
| **메신저/통화 앱 개발자** | 카카오톡, 라인, 줌 등 | API 단순, 문서 명확, 성능 가이드 |
| **녹음 앱 개발자** | 회의록·인터뷰 앱 | 후처리 모드 지원 |
| **IoT 제조사** | 스마트 스피커, 유아용 인형 | Raspberry Pi 등 ARM 환경 지원 |

---

## 4. 제품 비전 (Vision Statement)

> **"사용자가 말한 음성은 그대로 들리지만, AI에게는 다른 사람의 목소리로 들린다."**
>
> 사용자는 SDK를 켜고 끄는 것 외엔 아무것도 신경 쓸 필요 없다. 통화 상대방은 자연스럽게 듣고, 녹음을 가로챈 공격자의 AI는 화자를 식별하지 못한다.

## 5. 핵심 가치 제안 (Value Proposition)

| 사용자 그룹 | 가치 |
|---|---|
| 일반 사용자 | "내 음성이 AI 학습 자원으로 쓰이지 않는다는 안심" |
| 공인 | "딥페이크 영상의 음성 추출 자료로 내 발언이 사용되지 않음" |
| 기업 | "임원의 음성이 딥페이크 사기 시도에 쓰이지 않음" |
| 개발자 | "한 줄 통합으로 음성 보호 기능 추가, 별도 서버 인프라 불필요" |

## 6. 목표 (Goals) — 측정 가능한 형태

### 6.1 Phase 1 (Raspberry Pi prototype, 5월 중순까지)

| ID | 목표 | 측정 지표 | 목표값 |
|---|---|---|---|
| G1 | **화자 식별 방어** | WavLM-SV + CAM++ 평균 cosine distance (변형 vs 원본) | ≥ 0.40 |
| G2 | **음성 복제 방어** | OpenVoice2 + XTTS로 복제한 음성과 원본의 cosine distance | ≥ 0.35 |
| G3 | **음성 명료성 유지** | wav2vec2-xlsr-korean의 CER (변형 음성 입력) | ≤ 30% |
| G4 | **실시간성** | Raspberry Pi 4B에서 1초 음성 처리 latency | ≤ 200ms |
| G5 | **음질 청취** | 원본 vs 변형 ABX 청취 테스트 정답률 | ≤ 60% (랜덤 50%에 가까울수록 좋음) |

### 6.2 Phase 2 (Android SDK, 7월 말까지)

| ID | 목표 | 측정 지표 | 목표값 |
|---|---|---|---|
| G6 | **Android 통합** | Android Studio sample app으로 통화 보호 시연 | 동작 확인 |
| G7 | **모바일 latency** | Pixel 6 등 중급 안드로이드 기기 | ≤ 300ms |
| G8 | **메모리** | 추론 시 peak RAM 사용량 | ≤ 200MB |
| G9 | **API 단순성** | 통합에 필요한 코드 라인 수 | ≤ 10 lines |

### 6.3 학술 산출물 목표

| ID | 목표 | 마감 |
|---|---|---|
| A1 | 학회 논문 1편 제출 (KSC, ICASSP, INTERSPEECH 중 1) | 2025-09 |
| A2 | 깃허브 공개 + README/튜토리얼 | Phase 2 완료 시 |

## 7. 비목표 (Non-Goals) — 명시적 제외

이 항목들은 **이번 프로젝트 범위 밖**이다. 명시해두지 않으면 scope creep으로 일정 지연된다.

- ❌ **iOS 지원**: Android 우선. iOS는 v2 이후
- ❌ **클라우드 모드**: 온디바이스만 지원
- ❌ **학습 시 사용자 데이터 사용**: 오프라인 시뮬레이션 학습만
- ❌ **다국어 ASR 평가**: 한국어 + 영어 일부만. 일본어/중국어 미지원
- ❌ **음성 합성 (TTS) 기능**: 보호만, 합성 X
- ❌ **음성 인식 (ASR) 기능**: 평가 도구로만 사용, 사용자 ASR 제공 X
- ❌ **GUI**: SDK 형태만, 사용자 직접 사용 앱 X (Phase 2 sample app 제외)
- ❌ **암호화/통신 보안**: 변형은 음성 신호 자체에만 적용, 네트워크 보안 X

## 8. 위험 요소 및 대응 (Risks)

| 위험 | 영향도 | 대응 |
|---|---|---|
| RL 학습 수렴 안 함 | 높음 | Action space 단순화 (5-discrete), 사전 측정 데이터로 부트스트랩 |
| Raspberry Pi에서 latency 초과 | 높음 | 모델 경량화 (~10K params), ONNX 변환, 벡터 PRO 병렬연산 |
| 평가 모델 과적합 (특정 모델만 속임) | 중간 | 학습/검증 모델 분리, 다중 모델 평균 |
| 음질 너무 안 좋음 | 중간 | Psychoacoustic Masker hard-constraint, ABX 테스트 주간 측정 |
| 팀원 일정 차질 | 중간 | 2주 sprint, 매주 동기화, 모듈 의존성 명확히 |
| 평가에 쓰는 외부 모델 라이선스 문제 | 낮음 | 학술 사용 한정 명시, MIT/Apache만 채택 |
